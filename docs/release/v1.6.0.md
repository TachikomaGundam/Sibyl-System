## incident honestly recorded — including my own false lead, corrected

During this wheel an earlier attribution in these very files blamed the fresh-root
audit CONVENER for resetting the staging clone and losing a carrier commit. That
attribution was FALSE. True root cause, established by reproduction: this machine
holds TWO scratch roots — /tmp/opencode and /home/lab/tmp/opencode — and the seat
treated them as one, alternating between the twins and reading "vanishing work"
where there was only path confusion (an audit-copy `cp || cp` chain silently
created the /tmp twin and cemented the illusion). The carrier commits were never
lost; the convener never touched anything. The first local-only tag was still
re-minted — legitimately, because the argv-parser defect (see boundary) made the
publish gate 404 on its own CI invocation, caught by live dress rehearsal.
Discipline lessons absorbed: (1) ONE canonical scratch root from this wheel on;
(2) an incident attribution needs reproduction before it is written anywhere —
a wrong cause written into a shipping record is the same face-claim sin this
wheel's ledger fights in vectors, now applied to the seat itself; (3) the
convener-tool-narrowing item is retained on the v1.6.1 list only as a
principle-based hardening, explicitly NOT as something this incident proved.
