# release packet — v1.4.0

Owner-approved release round (2026-10-23, menu items 1+2 of the probe campaign that
this wheel also documents). Four doors, one law each:

- **security-chain cleanup.** `@opencode-ai/plugin` 1.15.13 -> 1.19.4 (aligned with the
  shipping engine generation) + `overrides` pin toml@5.0.1, the fixed release of the
  three quadratic/DoS advisories (GHSA-4qx8-w7c3-pj3p, GHSA-9j65-hcg3-gc64,
  GHSA-9qmh-m7c6-f92p; vulnerable range toml<=5.0.0, pulled transitively via
  effect). Override safety evidence: this package's own source references toml zero
  times; the full suite is green on the override; `npm audit --audit-level=high`
  exits clean and is now a standing CI step so a reintroduced chain fails on arrival.
- **private run dirs (0700).** Every directory the plugin creates — run dirs under
  `lane.runRoot` (default `/tmp`), per-run space dirs, the store dir, the six role
  sandbox dirs — is created mode 0700 with an explicit chmod behind it, immune to
  umask and to pre-existing world-readable leftovers. Tests lock the invariant.
- **the refused-launch law (F-W1b option 3, council run named in the tag header).**
  An explicit `--run-id` whose tool-staged `launch-context.json` is missing or
  malformed is refused at the door and the refusal is recorded inside the private
  run dir (`launch-refusal.json`) — a refusal that leaves no record is the
  absence-without-record class W2 forbids. The bare CLI lane keeps its named
  `UNVERIFIABLE` leg; once the chamber runner regenerates its run record, that face
  outvouches any contradicted staged claim ("record wins").
- **CI doors.** New push/PR workflow runs the same five offline doors as `ship.sh`
  plus `npm audit --audit-level=high`; the publish job switched from bare `npm test`
  to the full doors + audit; `engines: node >= 22` declared; stale doc numbers
  corrected (tool count, test count) and the two new laws documented in the README.
