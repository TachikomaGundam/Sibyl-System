# release packet — v1.3.6

Evidence-law wheel for the W1-v2 lineage detector, driven by two adversarial
findings from ballots on the v1.3.5 campaign (council sessions, quoted roles not
shas here): identical template rows were counted as independent convictions
(repetition inflates an index-keyed match set), and a pure ratio threshold is
escapable by an author who types under the majority line verbatim and generates
the rest. A third lesson, from the campaign's own staging: two mis-staged fixtures
burned full council rounds that a two-second offline check would have killed.

## law changes

- dedupe: lineage evidence counts DISTINCT sampled window contents; thirty copies
  of one typed line are one piece of evidence, not thirty (kills the reverse-s20
  false-conviction face).
- absolute floor: at least 8 distinct typed windows AND >= 30% of distinct samples
  convicts regardless of the majority line (kills the ratio-evasion face). The
  boundary is stated honestly: an author typing less than that and generating the
  rest reads independent BY DESIGN — the law is a coarse kinship detector, and the
  full-text containment path still convicts complete verbatim drafts instantly.
- dry run: previewLineage() + e2e/stagecheck.mjs reproduce the exact credit path
  (same functions, same time gate, same directory query) against the live engine
  store, so staging arithmetic is provable in seconds; parity between the dry run
  and the full assessIndependence path was verified on a fresh stage (identical
  counts, same face).
- receipts in this packet follow the anchor law: no self-referential or
  amend-killable literals. Boundary references use ONLY the previously published
  tag v1.3.5 — an ancestor ref that this wheel cannot rewrite; the carrier sha
  itself rides the tag header.
